解决的问题

聊天给出的建议还需要人去执行；任务一长，进度、文件变化和完成依据容易分散。希望在一个工作台里继续任务、查看过程并核对结果。

我做的工作

围绕任务入口、工作区选择、授权与执行反馈梳理交互；结合 AI 辅助开发，迭代桌面界面、工具能力和验收流程。

实现重点与产品取舍

  1. 把执行与验证分开

    任务先形成计划与验收条件，再由工具执行；验证模块依据文件、命令和工具结果判断是否完成，并记录需要返工的条件。

  2. 长任务保留进度

    SQLite 保存任务队列与执行片段。达到分段边界时保存检查点与上下文，支持继续处理；运行中也能停止或引导任务。

  3. 让权限与变化可见

    聊天和工作区工具有明确边界。选择目录后才使用项目工具，授权和执行轨迹保留记录，便于检查文件差异与任务结果。

交付内容与使用条件

  • Windows 桌面界面与本地执行核心。
  • 持久任务、工具调用、执行轨迹与文件差异查看。
  • 计划、验证与返工记录组成可检查的任务闭环。

桌面程序需要在 Windows 本机运行，模型调用与远程 MCP 需要相应配置。本页公开介绍核心流程，源码入口需要权限。
